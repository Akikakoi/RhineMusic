# RhineMusic 曲库与播放面板

2026-09-21。阵列接入黑胶卡片之后的两步：滑套正面印刷曲目信息（第 3 步）、详情右栏改为 NOW PLAYING（第 4 步）。

## 数据层

- 新增 `content/tracks.json`：五列分类（观测室 / 收录曲 / 电子实验 / 夜间频率 / 特别收录）× 8 = 40 条，字段 `id / title / artist / category / duration / file / pending`。
- 已入库 6 条（真实音源）：`atmosphere.ogg`、`motif.ogg`、`pulse.ogg`（三条项目配乐，各 53.3s）、`observatory-preview.mp3`（53.4s）、`doriko、初音ミク - 歌に形はないけれど.mp3`（332.3s）、`坏苹果（车载dj版）.mp3`（459.7s）。
- 其余 34 条为**占位曲目**（`pending: true`，无时长与音源），用于按用户要求撑满五列阵列；界面上以 `--:--` 时长、`PENDING · 待入库` 与 `占位曲目` 标注区分，不会被误认为真实曲目。
- `src/data.ts` 改为读取曲库，函数名与签名沿用（`records / categories / archiveColumns / columnFiles / fileLocation / fileAtSlot`），因此 `archive-loop.ts` 与 `scene.ts` 的阵列、槽位、循环逻辑无需改动；新增 `formatDuration()`。
- 遗留命名：`archiveColumns`、`records` 仍是档案时代的名字，语义已变为曲库分类与曲目列表；重命名会牵动多处调用点，未在本轮处理。

## 第 3 步 · 滑套正面印刷

- `scene.ts` 的画布标签从「档案索引签」改为「唱片封面」：画布 1024 × 605（与印刷区 4.4 × 2.6 同比例），平面从 0.99 × 0.46 放大到 4.4 × 2.6，位置移到正面中央 (0, 1.75, 0.245)。
- 内容：左上 `RHINE MUSIC / AUDIO ARCHIVE`，右上 `NO.00X` 与分类，中部大曲名（超宽自动换行，第二行省略号收尾）与歌手，底部时长与状态（`READY · 本地音源` / `PENDING · 待入库`），另有 10% 透明度的标志水印。
- 资产侧配合：索引签从标签平面原位移到左上角 (−1.9, 3.36)、尺寸 1.0 × 0.36，让开印刷区避免与印刷平面互相穿插。

## 第 4 步 · 详情右栏 NOW PLAYING

- `renderDetail()` 重写：kicker 改为 `TRACK <id>` + `READY/PENDING`，标题改为曲名 + 歌手，元数据改为曲库分类 / 时长 / 音源 / 状态；页签改为 01 播放、02 歌词、03 播放记录（歌词与播放记录为占位说明）；动作区为收藏曲目与播放按钮；导出档案链接移除。
- 播放面板：NOW PLAYING 区（曲名、歌手、分类）、进度条、已播/总时长、走带（上一首、播放暂停、下一首、循环模式），与设置弹窗里的迷你播放器**共用同一条音频链路**——`audio.configure({musicTrack})` 选曲、`audio.setPaused()` 播放暂停、`audio.skip(±1)` 切歌、`audio.seek()` 进度，状态来自 `rhine-music-state` 事件。未入库的占位曲目点击播放会提示「尚未入库」。
- 检索弹窗、收藏弹窗、导航与页脚文案同步改为曲库语义（TRACK INDEX / SAVED TRACKS / 曲目、歌手、分类）。
- `src/style.css` 追加 NOW PLAYING 样式，使用 `--theme-*` 变量，双主题通用。类名统一加 `playback-` 前缀：旧播放器遗留的 `src/player.css` 里已有 `.transport` 规则（按钮被压到 30 × 26），直接复用类名会互相污染。
- 详情面板改为重建时捕获渲染异常并提示，避免静默留下空面板。

## 歌词与播放记录页签（2026-09-21 追加）

- `src/lyrics.ts`：LRC 解析（一行可带多个时间标签，忽略 `[ti:]` 等元信息）、按 URL 取用并缓存、`activeLyric()` 求当前行、`formatLyricTime()`。模块不依赖其他源码，可直接在 Node 里跑用例。
- `src/play-log.ts`：播放记录写入 localStorage（上限 40 条，同一曲目只保留最近一条），`formatPlayTime()` 输出时分。
- `content/tracks.json` 新增可选 `lyrics` 字段（`public/lyrics/` 下的文件名）；当前为 RM-001 与 RM-004（项目自有曲目）配了段落提示 LRC。**没有为收录曲编写歌词**——第三方曲目不做歌词转录，界面显示「尚未关联歌词文件」。
- 同步高亮只在该曲目正在播放时生效（`state.wanted === 播放列表下标 && playing`），否则列出全部歌词供阅读；高亮行会滚动到面板中部，减少动态效果时改为瞬时定位。歌词面板带上下渐隐遮罩，仅在同步状态启用。
- 播放记录在 `rhine-music-state` 里于「真实起播且曲目变化」时写入；停止后清空去重标记，便于重复播放同一曲目时再次记录。页签提供「清空记录」，并区分占位曲目（无法播放，不会出现）。
- 复核入口支持 `?scene=detail&tab=notes|history` 指定初始页签。注意 `select()` 会在详情内换曲目时重置回播放页签，重置逻辑因此只在 `mode === "detail"` 时执行，否则会吃掉启动时的初始页签。

验证：
- Node 直接跑模块用例：`RM-004.lrc` 解析出 8 行且时间正确；`activeLyric` 在 0/5/13/22/31/40/47/52/60 秒分别返回 0→7 且越界后停在末行；`formatLyricTime(332.9) = 05:32`；无 localStorage 时 `readPlayLog()` 返回空数组而不抛错。
- 无头 Edge（1920 × 1080 桌面构图）逐页截图：歌词页签显示时间码与段落文字，播放记录页签显示空状态、本机记录数与「清空记录」。截图里正文偏淡是详情解密的揭示阶段尚未走完（无头环境不触发交互），不是样式问题。

## 唱片滑出行程

- 行程由 2.75 收到 1.85。桌面构图实测：右栏紧贴卡片右边缘（可见模型空间里卡片右缘与面板左缘几乎同一条线），因此**横向任何行程都会落到面板之下**；行程越长越多压在面板后面，收短后唱片只在卡片右上露出较小的一截，中心标签被卡片挡住。
- 若要让唱片完整可读，可选方案：把滑套开口改到上边缘、唱片向上抽出（上方是阵列背景，没有遮挡）；或让唱片在抽出时同时向观察者方向前移一段，压在封面之上。两者都需要改资产或映射方向，待确认后再做。

## 播放跟随（2026-09-21 修复）

现象：播放器切歌（面板上的上一首／下一首、设置里的迷你播放器）后，音乐换了，但阵列选择、卡片封面与右栏信息都停在原来那一首。

根因：界面只跟随「阵列选中的曲目」，从不跟随「正在播放的曲目」。选曲走 `select()`，而音频切歌只更新音频引擎状态，两边没有任何回写。

修复：`rhine-music-state` 监听里，当处于播放状态、曲目下标变化且能在曲库中按标题匹配到条目时，调用 `select(index)` 让阵列选择跟随（带 `followingPlayback` 重入保护）。停止播放时清空记录标记，便于再次播放同一曲目时重新写入播放记录。

实测（`puppeteer-core` 驱动系统 Edge，真实按键与点击，`--autoplay-policy=no-user-gesture-required` 允许无手势起播）：

| 步骤 | 模式 | 界面 |
| --- | --- | --- |
| 初始 | archive | AMBIENCE（-001） |
| 选中 MOTIF | archive | MOTIF（-002） |
| 点播放 | detail | 封面 MOTIF、右栏 MOTIF、走带显示暂停、进度 00:03 |
| 点下一首 | archive | 选择跟随到 PULSE（-003） |
| 再进详情 | detail | 封面 NO.003 / PULSE、右栏 PULSE、进度 00:06 / 00:53 |

副作用：在详情页按下一首会回到阵列（沿用项目原有的「详情中换选先回到预览」规则）。若希望留在详情只替换内容，需要给场景增加「原地换选」路径（不收起抬升、把模型移到新格位并重画封面），目前未做。

回归入口：`npm run check:playback`（`scripts/check-playback.mjs`，puppeteer-core 驱动系统 Edge，`CHECK_URL` 指定地址、`CHECK_SHOTS` 输出截图）。检查项：选中 002 → 进入详情播放 → 进度推进 → 点下一首后阵列选择跟随到 003 → 再进详情标题为 PULSE；任一不成立即以非零码退出。

> 说明：本轮为定位这个联动问题引入了 `puppeteer-core` 开发依赖（不下载浏览器，直接驱动系统 Edge），并把探针固化成上面的检查脚本；不需要时可移除依赖与脚本。

## 选曲即播与详情内原地换选（2026-09-21 追加）

### 选曲即播放

- `selectForPlayback()`：选曲后把该曲目设为播放目标，停顿 350ms 再起播。停顿是为了连续浏览（方向键连按、拖动阵列）时不会反复重启音频，只播放最终停下的那一首；设置里关闭了音乐、或该曲目已在播放时不动作。占位曲目没有音源，不会进入播放目标。
- 触发点：方向键与阵列拖动导航（`stepFile` / `stepColumn`）、底部刻度点击、检索/收藏结果点击、进入详情（`openFile`）。

### 详情内原地换选

- 场景新增 `swapSelection(index, navigation)`：保持抽取高度与解密状态，只更新选中格位与封面；旧卡片交给 `detachOutgoing()` 生成的归位副本下降回阵列。原来 `select()` 在详情中换选会先收起抬升再回阵列，现在留在详情。
- `detachOutgoing()` 从 `select()` 中抽出，两处共用；顺带修掉一个既有缺陷：归位副本的封面画布写死 1024 × 440，而封面画布已改为 1024 × 605，复制出来会被压扁。
- `main.ts` 新增 `swapInDetail()`（换选 + 刷新右栏 + 选曲播放）；方向键与播放器切歌在详情模式下都走这条路径。

### 一个必须记住的坑

播放跟随最初写成「只要播放曲目与选中曲目不一致就跟随」，结果与用户选择互相抢：选曲后音频还没切过去的那几帧，每次播放状态刷新都把选择拉回上一首，表现为「按方向键没反应」。现改为**只在播放曲目真正变化时**（`state.track !== lastPlayedTrack`）跟随一次，同时播放记录也复用这个变化点。

### 面板版式

- 详情面板的桌面最大高度改为 `calc(100% - 430px)`：曲名与文件名变长后内容会顶到页脚。
- 长曲名（> 16 字）使用 `h2.compact`（30px），元数据行距与下边距收紧，NOW PLAYING 去掉与上方重复的歌手行，占位提示只对占位曲目显示——保证 SAVE TRACK / PLAY 这一行留在可视区内。
- 元数据里的音源文件名用省略号收住（`title` 属性保留完整名）。
- 黑胶材质下调环境反射（color #0e0e11、roughness 0.42、clearcoat 0.5、envMapIntensity 0.35），大尺寸下才读得出「黑」而不是一块灰盘。

回归入口：`npm run check:playback`，覆盖四项：选曲即起播、进入详情、详情内原地换选、播放器切歌在详情内跟随；`?scene=` 复核模式下页面暴露只读的 `window.rhineMusicState()` 供检查读取真实播放状态。

## 点击抬起的卡片进入播放界面（2026-09-21 追加）

现象：在阵列里点已经抬起（最高）的那张卡片没有任何反应，进不了播放界面。

根因：选中格位的阵列实例是隐藏的，抽取模型挡在那个格位上，因此 `pickCell()` 命中模型时返回的是 `selectedCell` 本身；外壳收到 `onSelect(同一个 index, 同一个格位)` 后只走了一次「重新选中」，没有后续动作——点自己没有语义。

修复：场景新增只读的 `selectedCellSnapshot`，外壳在 `onSelect` 里判断「命中的格位就是当前选中格位」时调用 `openFile()`（比只比 index 更准：同一个曲目的循环副本是不同格位，不该误开）。于是「点一下选中、再点一下打开」成立，与 `ACCESS FILE` / Enter 并存。

回归入口 `npm run check:playback` 新增第 5 项：用场景投影（`window.rhineSceneStats().topLeft / topRight`）算出抬起卡片在屏幕上的位置再点击，断言模式进入 detail。抬起卡片会被后排卡片部分遮挡，脚本按几个纵向位置重试。

> 复核模式的只读钩子：`window.rhineMusicState()`（播放状态）与 `window.rhineSceneStats()`（场景投影与选中格位）。

## 播放中可调进度（2026-09-21 追加）

- 详情面板原先进度只是一根 2px 的展示条，现在换成可拖动的 `input[type=range]`（`#playback-seek`），用 CSS 把轨道与滑块压成同一根细线：轨道用 `linear-gradient` 以 `--seek-progress` 变量填充已播部分，滑块 10px 圆点为杏金色。键盘（←/→/Home/End）与指针拖动都可用。
- 拖动期间用既有的 `musicSeeking` 标记（与设置里的迷你播放器共用）避免状态回写抢数值；拖动时同步更新已播时间。
- `updatePlaybackPanel()` 里：只有当选中曲目就是正在播放的那一首时进度条才可用（否则禁用并回到 0），因为进度对别的曲目没有意义。
- `TerminalAudio.seek()` 放开了暂停限制：暂停时也能定位，位置先记下，恢复播放从该处开始。

回归入口 `npm run check:playback` 新增第 2b 项：播放中把进度设到 70%，断言真实的 `currentTime / duration` 落在 0.6–0.86，并断言进度条未被禁用。

- 360° 查看器仍为档案盒模型（`archive-assembly.glb`），其标签平面仍按旧的 0.99 × 0.46 尺寸显示新封面，会被压扁；切换查看器资产时一并处理。

- `src/player.css`、`src/archive-playground.ts` 等旧转向遗留文件仍在仓库里，其中 `.np-*`、`.transport` 规则已与现界面无关，建议后续清理。
- 唱片滑出 2.75 时，唱片有相当一部分位于封面右侧、会被右栏遮住；若希望唱片完整可见，需要调整滑出行程或详情镜头构图。
